# 确认入库与中断续做

仅在用户已授权当前作品入库时使用此流程；一次确认后继续完成必要步骤，不因工具中断反复索取相同确认。用户另有明确范围时以其指令为准。

## 先确定实际状态

检查库路径、首页、模板、维护说明、CSV、Excel以及相关笔记／附件。不要把旧交接说明的状态当作现状，也不要直接运行未审查的旧构建脚本。

通过DOI（规范化URL前缀、大小写）、标题、作者年份、已有ID和PDF身份综合查重；新颖性复核不是入库的前置阻塞。候选匹配可能只在笔记或总表一侧出现，需检查部分写入状态。

- 同一作品已完整入库：打开已有成果，按本次要求补缺或说明已存在，不新增编号。
- 已有笔记但缺总表／附件：沿用原ID补齐。
- 已有总表但缺笔记：沿用原ID恢复；先确认文件是否被移动或改名。
- 确为新作品：依据笔记、CSV和Excel已用ID选择 `LIT-入库年-序号`，以当前库命名惯例为准。入库年与发表年分开，不硬编码2026或已入库篇数。写回前再次核对无碰撞。

## 目标文件与知识关联

| 内容 | 库内约定 |
|---|---|
| 主笔记 | `Literature/LIT-YYYY-NNN.md` |
| 原文副本 | `pdfs/LIT-YYYY-NNN.pdf`；保留原始文件 |
| 图表 | `attachments/LIT-YYYY-NNN/Fig-1.png`、`Table-1.png`；跨页增加明确后缀 |
| 主题 | `Topics/`；先复用同义主题 |
| 方法／理论 | `Methods/`；明确理论视角与算法的区别 |
| 候选问题 | `Research-Questions/`；先查重再分配RQ编号 |
| 导航 | 首页、主题索引、方法索引、研究问题池 |
| 总表 | `文献总表.xlsx`和`文献总表.csv` |

原图嵌入如 `![[attachments/LIT-YYYY-NNN/Fig-1.png]]`，PDF用可打开的内部链接。表格中的wikilink别名分隔符需转义，例如 `[[Literature/LIT-YYYY-NNN\|短标题]]`，保持表格列数正确。

关联节点应有实际内容和来源，不为图谱好看创建空节点。跨文献联系标明互补、方法比较或尚待验证，不把连线当作已证实学术关系。不批量重写无关旧笔记。

## 总表字段与状态

保持以下18列及顺序；若当前库已由用户调整，先适应实际schema，不强行覆盖：

```text
文献ID,论文标题,作者与年份,期刊/会议,DOI,研究主题,核心研究问题,数据来源,研究方法,主要发现,创新贡献,研究局限,可借鉴之处,潜在研究问题,阅读状态,详细笔记文件,Zotero条目,最后更新
```

主笔记记录完整证据；总表每篇一行、写摘要，不堆放全文。新AI整理条目在总表通常为“待复核”，笔记为“AI初读待人工核对”。已有人工作出的阅读状态不降级或自动改成“已整理”。Zotero未核实填“未核对”；最后更新使用当前客户端日期，不代替论文发表／采集时间。

编辑Excel时优先使用环境中当前可用的电子表格技能与运行时，先查看现有工作表和样式，定位表头及最后数据行，不假定固定行号。保留原工作表、记录、格式、表对象、筛选、冻结窗格、校验和日期类型；扩展新行即可。

Excel是日常维护入口，但不能假定始终与CSV一致。先比较旧记录；若不一致，保留差异、判断本次可安全合并的范围，必要时澄清有冲突的用户编辑，不能静默用一份覆盖另一份。新记录由同一批内容更新两份，CSV使用UTF-8（可含BOM）。没有后台监听或双向同步服务，不声称已建立。

## 保存与验收

1. 先复用 `D:\文献阅读预览`（或用户指定的预览目录）中本篇已确认的文档和全部图表，检查源文件身份及完成情况。入库用的笔记、PDF副本方案、索引和总表可在会话工作目录暂存，记录拟修改文件的当前内容／哈希；这种入库暂存不改变预览成品的D盘保存约定。
2. 对需要修改的现有文件，先存可恢复备份到 `data/index-backups/时间戳-文献ID/`。Markdown备份用`.bak`防止产生重复文献节点。
3. 写回前检查现有文件未被用户或其他进程改动。已有目标内容相同则跳过；内容不同且不属于本次授权修改的目标，先比较，不能强制覆盖。根据运行环境取得必要文件权限，不另行添加用户审批门槛。
4. 保存后核对新文件与源、已有笔记保留情况、内部链接目标、图表清单完整性、表格显示、Excel/CSV18字段逐项一致及ID／DOI唯一性。日期比较统一语义，不能把Excel日期序号与CSV字符串直接判为冲突。
5. 视觉检查新图表及受影响的电子表格区域，保留可追溯验证结果；不反复检查已通过且未变化的部分。
6. 若某部分失败，明确已完成与缺失项、保留暂存成果和备份。后续按同一ID补齐，不将中断当作重新导入新作品。

完成后给主笔记链接、图表数量、记录更新结果和备份位置。文件系统写入被验证不等于已检查Obsidian界面；未实际操作就不声称界面已刷新。
